# 📚 AI Research Assistant — Retrieval-Augmented Generation (RAG)

A portfolio-ready Python/Streamlit app that lets users upload PDF research papers, retrieve relevant passages, and generate answers grounded in the documents with numbered citations.

## Features

- Upload multiple text-based PDF files.
- Extract text with page-level metadata using `pypdf`.
- Split long pages into overlapping passages.
- Retrieve relevant passages with TF-IDF vectorization and cosine similarity.
- Generate grounded answers with the OpenAI Responses API (optional API key).
- Show source file names, page numbers, similarity scores, and supporting excerpts.
- Run retrieval without an API key.

## Architecture

```text
PDF upload → text extraction → overlapping chunks → TF-IDF index
                                                     ↓
User question → vectorized query → top-k passages → OpenAI LLM → cited answer
                                         ↓
                              source excerpts in UI
```

**Why RAG?** The application retrieves evidence from user-provided documents and supplies only those excerpts to the language model, rather than relying solely on general model knowledge. This reduces—but does not eliminate—hallucinations. Citations are generated by the model and should be verified against the displayed source passages.

## Setup

Requires Python 3.10+.

```bash
git clone https://github.com/YOUR_USERNAME/ai-research-assistant.git
cd ai-research-assistant
python3 -m venv .venv
source .venv/bin/activate  # Windows PowerShell: .venv\Scripts\Activate.ps1
pip install -r requirements.txt
cp .env.example .env  # Windows: copy .env.example .env
```

Edit `.env` and add your OpenAI API key to enable generated answers. **Never commit `.env` or API keys.** You can also paste the key in the app sidebar. The model defaults to `gpt-4.1-mini`; update it if needed for your account.

```bash
streamlit run app.py
```

Open the local URL shown by Streamlit (usually http://localhost:8501). Upload one or more PDFs, enter a question, and click **Find answer**.

## Limitations and responsible use

- Scanned/image-only PDFs require OCR, which is not implemented.
- TF-IDF uses lexical matching; it can miss paraphrases or conceptually similar wording.
- Uploaded content is held in app session memory, not stored in a database.
- When using an OpenAI key, retrieved text excerpts are transmitted to the API; do not upload confidential documents unless authorized.
- Model answers can be incorrect or contain inaccurate citations. Check the displayed excerpts before relying on an answer.
- Large PDFs may increase memory use and response time.
- This is a demonstration tool, not a production-grade secure document service.

## Future improvements

- Replace TF-IDF with sentence embeddings and a vector database (FAISS/Chroma).
- Add OCR for scanned documents.
- Add evaluation metrics (retrieval precision@k, citation faithfulness).
- Add user authentication and per-user document isolation for deployment.
